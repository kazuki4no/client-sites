# RiRi hair サイト

千葉県成田市の美容室「RiRi hair リリヘアー」の公式サイト。ビルド工程のない静的サイトで、このフォルダの中身がそのままサーバーに置かれる。編集を頼むのはお店のスタッフで、HTMLの知識はない前提で対応する。

## 話し方

- 専門用語を使わず、何を変えたかを「どのページの、どこを、どう変えたか」で短く伝える。
- 変更後は「ブラウザで ○○.html を開いて確認してください」と案内する。
- 文章はお店が書いたものをそのまま使う。頼まれていない言い回しの修正や誤字の訂正はしない(気づいたら提案だけする)。

## ファイル構成

| ファイル | ページ |
|---|---|
| `index.html` | トップ(NEWS・GALLERY・WORKS・Instagram・MAP) |
| `news.html` | お知らせ一覧 |
| `post-<番号>.html` | お知らせの記事 1 件ずつ |
| `works.html` | 全記事の一覧(写真つきのグリッド) |
| `service.html` | メニュー紹介(ヘア・ネイル・カフェ・スカルプインク・アイラッシュ・脱毛) |
| `price.html` | 料金表 |
| `staff.html` | スタッフ紹介 |
| `with.html` | RiRi with...(提携先) |
| `kodawari.html` | こだわり |
| `first-visit.html` | 初めてご来店のお客様へ |
| `style.css` | 全ページ共通のデザイン |
| `images/` | 写真 |

ナビゲーションとフッターは全ページに同じ HTML が入っている。メニュー項目を変えるときは全 HTML ファイルを直す。

## よくある作業

### お知らせを 1 件追加する(直す場所は 4 つ)

1. 既存の `post-*.html` を複製して新しい記事ページを作る。ファイル名は `post-YYYYMMDD.html`(同じ日に 2 件目なら末尾に `-2`)。日付・タイトル・本文を入れ替える。
2. 新しい記事の下部ナビ「古い記事」を、それまで最新だった記事に向ける。それまで最新だった記事には「新しい記事」リンクを足す。
3. `news.html` と `works.html` の一覧の先頭に追加する(NEWS に載せない記事は `works.html` だけ)。
4. `index.html` の NEWS は新しい順に 3 件だけ表示する。先頭に足して一番古い 1 件を外す。WORKS 欄も最新記事に合わせて更新するかはスタッフに確認する。

### 料金を変える

`price.html` の該当行の金額を直す。`service.html` にも主なメニューの金額を載せているので、そちらもそろえる。同じメニューが複数箇所に出てくる(例: 「親子でご来店で特権をご用意」は 2 回、ヘアリセッターはカットとセットメニューの両方)ので、全部そろえる。

### 写真を差し替える・追加する

- `images/` に入れる。ファイル名は半角英数字とハイフンのみ(日本語のファイル名は公開スクリプトが送れない)。
- スマホの写真は大きすぎるので、長辺 1600px 程度の JPG に縮小してから使う。
- 写真の枠は `<div class="ph" data-file="images/xxx.jpg"><img …></div>` の形。画像が無いと枠にファイル名が出る仕組みなので、この形を崩さない。

## 公開(サーバーへのアップロード)

- 公開は `./publish.command --yes` を実行する。前回から変わったファイルだけが送られる。
- **スタッフが「公開して」「アップして」と言うまで実行しない。** 編集しただけでは公開しない。
- 実行前に、公開されるページを一言で伝える。実行後は、スクリプトが表示した件数と、× 印(失敗)があればそのファイル名を伝える。
- 「接続先が未設定」と出たら、スタッフに `publish.command` をダブルクリックして FTP 情報を入れてもらう。FTP のパスワードをチャットに書いてもらったり、ファイルに書いたりしない(Mac のキーチェーンに保存される)。
- サーバー上のファイルを消す機能は無い。ページを削除したいと言われたら、リンクを外したうえで、サーバー側の削除は別途必要だと伝える。
- `.publish-config`、`.publish-state`、`publish.command`、この `CLAUDE.md` はサーバーに送られない。
